## ⚠️ Read this before touching hardware

- **`slix2-gold-30mm`** — ⚠️ DO NOT WIPE -- GEN3 CANDIDATE, 2026-09-26. Blocks 0x10/0x11 hold this card's UID in the reversed gen3 layout (uid[7..4] then uid[3..0]), and 0x14/0x15 hold a value matching the V3 config-mode signature in 5 of 8 bytes, positionally, with 0x14 one BIT away. The probe's gen3_signature:false came from an exact == against two constants and cannot tell 'not V3' from 'V3 with a signature we do not have'. The release notes carry an attributed report that zeroing 0x14/0x15 on an un-finalized V3 card BRICKS IT PERMANENTLY -- those are blocks 20 and 21, which any wipe reaches immediately, and this card never refuses a write so the sweep would not stop early. It also ACCEPTS writes above its advertised 79 (blocks 80 and 100 written and read back), so it has no discoverable edge by read or write. See .notes/gen3-candidate-slix2-gold.md before touching it.

The **original** columns are write-once, recorded before any probe wrote to the tag.
A tag marked **\*** has NO pre-write read: it was already written to before the first
instrumented read, so its factory identity was never captured. What such a row shows for
identity is `?`, and what the card presents instead is a costume recorded separately in
the JSON. Its **blocks** cell is still a real measurement. Read that tag's note before
citing any field of it as silicon.
A blank restore column means the snapshot came from `info`/`capacity` rather than the
`baseline` probe, so there is no per-block record to restore from.

**vs listing** compares what the seller claimed against what was measured. A mismatch is a
result, not an error -- an advertised count below the listing is the programmed-count case and
one above it is the phantom tail. Neither side gets corrected.
